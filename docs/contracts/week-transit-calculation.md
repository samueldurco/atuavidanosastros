# Semana — experimental nominal transit-series contract

The independent [nominal temporal search](week-temporal-search.md) and [bounded 1.2.0 snapshot](week-temporal-calculation.md) do not change this 1.1.0 sampled snapshot or certify complete windows.

`atv-week-reading-calculation/1.1.0` adds deterministic sampled transit/natal comparisons to the Week E1 base. It is a separate internal composition, selected only with an explicit operator-owned `experimentalWeekTransitPolicy`. There is no default orb policy or editorial approval. Configuration with both this policy and `experimentalWeekBase: true` fails rather than choosing a version implicitly. The original thirteen default bases, publication gates and R$0 automatic spend remain unchanged.

The existing version 1.0.0 calculator still validates the input and all dates before provider work, obtains one natal chart and seven consecutive 12:00 UTC sample charts, captures input, checks cancellation and shares no cache across requests. This extension calls that calculator unchanged, then projects all 100 ordered transit/natal body pairs at each sample (700 comparisons, including ten same-body pairs). Natal and transit roles remain distinct. The context, including declared timezone/theme from request v2, does not alter geometry. Dates retain the engine range 1900-01-01–2099-12-25; these are UTC samples rather than local-day coverage.

Each series contains seven full-precision nominal separations, seven aspect kinds and corresponding deviations from the exact aspect angle (`orbDegrees`), with null kind/deviation when no configured rule matches. Orbs retain the engine's inclusive comparison without a classification epsilon. Six `separationChangesDegrees` are the successive separation differences, in degrees. A positive value means the sampled angular separation increased; a negative value means it decreased. Neither establishes applying/separating motion, closeness to any particular aspect, uninterrupted change, a station, an intervening exact transit or favorable timing. Display rounding to six decimals never enters the arithmetic or classification.

Geometry is the minimal nominal difference between tropical longitudes. Transit and natal retain their own ecliptic-of-date epochs; no common-epoch transformation is performed. The aspect policy is captured/canonicalized before awaited provider work, retained in the calculation data and named in one dedicated policy fact. The source of every pair fact identifies the cross-aspect algorithm and Week projection version. Precision is not certified, the assumed longitude error is null and all aspect stability remains unknown. Retrograde booleans do not infer continuous motion.

The outer facts preserve all 88 version 1.0.0 calculated facts, add one explicit-policy fact and 100 series facts, then preserve the optional exact reported context as the final fact: 189/190 unique facts. The unchanged generic runtime limits remain 400 facts, 2,000 UTF-16 units per display, 300 per source and 200,000 UTF-8 bytes per snapshot. Oversized snapshots fail; nothing is truncated or promoted.

To fit those limits without losing the seven input snapshots, the versioned encoding stores their identical natal projection once in `data.natalBasis`. Each `data.samples` entry retains the original snapshot metadata, original limits and its original data except `first`; its facts are represented by the outer natal and corresponding daily fact groups. Reconstruction restores `first`, restores the ten natal facts, and reverses the known daily ID/display/source prefixes for the eleven sample facts. This reproduces each complete context-free version 1.0.0 Leitura da Data snapshot. The compact sample alone is not a standalone Date snapshot; consumers must respect this encoding rather than applying the Date guard directly to it.

`validWeekTransitProjection` inspects original JSON descriptors, reconstructs all seven Date snapshots, invokes the original Week and Date validations, recomputes the complete new projection and compares it canonically. Missing/extra fields, additional compact-sample facts or natal copies, modified numbers, classifications, policy, limits, provenance, fact text/source, ordering, hidden properties, symbols, accessors, sparse arrays and unsupported prototypes are refused. Persisted coherence does not authenticate a provider, bind the calculation to an authorized request or certify engine accuracy.

The runtime can persist and reopen this experimental version only through its existing explicit product allowlist and processing authority. The legacy Week editorial profile deliberately refuses version 1.1.0 as `calculation_invalid`; its 88/89-fact interpretation, PDF/reader and Lab corpus remain version 1.0.0. No conversion/downgrade, new paid calls, quota changes or release are implied. A separate complete temporal/editorial adaptation remains necessary before this version can reach the product result.

E1 remains **EM_EXECUCAO**: this WU provides sampled series and between-sample comparison, not complete continuous temporal trends/windows. Events, windows, intensity, houses, angles, interpretation, calendar, reminders and alerts are not produced. E2/E5 and legitimate policy/editorial approval, engine homologation and hosted validation remain pending. The architectural promise of useful trends/windows is still a requirement; this version does not close it.
