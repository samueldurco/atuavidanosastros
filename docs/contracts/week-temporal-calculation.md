# Semana — bounded temporal calculation

`atv-week-reading-calculation/1.2.0` projects the [nominal seven-day search](week-temporal-search.md) into a `CalculationSnapshot`. The operator must explicitly configure `experimentalWeekTemporalPolicy`; this mode is mutually exclusive with `experimentalWeekBase` and `experimentalWeekTransitPolicy`. Default coverage still contains thirteen calculators and excludes Week. Neither configuration nor persistence authorizes publication, a paid provider, policy approval or interpretation.

## Input and computation

The worker validates the Week workflow, birth input, declared context, seven UTC dates and closing engine-supported instant before provider work. It captures the request and policy before awaiting the provider. One validated natal chart supplies the ten natal tropical longitudes. Request-local, validated Caelus calls provide each searched transit instant at UTC/geocentric reference coordinates; no local houses are inferred from the declared theme, location or timezone. Every evaluation is checked at the natal boundary, with abort fences. The search retains its 169 hourly observations, all 100 ordered pairs, versioned policy, nominal events and grid-connected candidates. The closing 00:00 UTC instant is an observation boundary, not an eighth product day. Engine range and 2,048-evaluation, 4,096-event and 2,048-window budgets remain unchanged.

## Persisted encoding

The complete refinement trace remains in local evidence. `data.rows` is an ordered tuple list `[millisecondsFromStart, tenFullPrecisionLongitudes, calculatedAtUTC, deltaTSeconds]`, in the canonical body order. It retains the 169 hourly rows and only the final observed `from`/`to` endpoints of each event; equal instants are deduplicated. No rounding, interpolation, fabricated provider point or event truncation is used. The snapshot also retains the natal input, positions and provenance; the shared transit source provenance, exact policy, all event brackets, candidate windows and declared context. The 11 facts describe the search and body-specific counts, with explicit experimental limits. Overflow of the unchanged **200,000 UTF-8 byte** runtime bound rejects the calculation rather than removing evidence. The measured synthetic real-engine example is **126,875 bytes**, 336 retained rows, 86 events and 34 candidates; sizes vary by chart and policy.

`validWeekTemporalProjection` inspects original JSON descriptors and dense arrays; validates the version, natal/engine/time basis, grid, policy and row domains; checks every observed final sign bracket and the maximum 60-second width; rederives grid contacts, grid-implied crossings and windows in canonical order; and compares facts, limits and all fields with a canonical snapshot. It rejects missing/extra evidence, hidden fields, symbols, accessors, unsupported prototypes and size overflow. The row time plus per-row `calculatedAtUTC`/`deltaTSeconds` and common provenance preserve source context, but persisted coherence is not a cryptographic provider attestation or proof that an arbitrary changed longitude was never tampered with. The runtime must establish its own authorization and source boundary.

The version retains the search's explicit uncertainty: hourly sampling and shortest-arc unwrapping may miss reversals, tangencies, multiple turns and sub-grid excursions. A bracket width is temporal resolution, not celestial accuracy. Candidate windows do not prove continuous occupancy, favorability, intensity, applying/separating motion or complete coverage. Tropical natal and transit epochs are not transformed to one epoch. The motor, aspect policy, interpretation and release remain unapproved. A separate [bounded editorial profile](week-temporal-editorial.md) now accepts this verified fact envelope for structural draft review. Complete interpretation, approval, hosted acceptance and E2/E5 remain separate work.
