# Saved natal profile to Preview do Par — atv-pair-request/1

Local implementation only. `pair-preview` remains disabled; this bridge does not approve an engine, model, prompt, interpretation or release.

`POST /api/workflows/pair` accepts exactly `{requestKey,input}`. Input has six fields: `version: atv-pair-request/1`, `productId: pair-preview`, positive integer `expectedRevision` below 2147483647, `partner`, `consent` and `partnerConsent`. No owner, owner birth, names, contact details, gender, relationship label, questions, free context or sharing destination are accepted.

`partner` contains exactly the six BirthInput fields (`localDateTime`, `utcInstant`, `timezone`, `latitude`, `longitude`, `locationSource`) plus `timePrecision: EXACT`. Dates/times must be canonical civil/UTC strings with seconds and optional one-to-three fractional digits. UTC must be between 1900-01-01 and 2099-12-31 inclusive. Coordinates are finite and bounded by ±90/±180; locationSource is nonempty text up to 80 characters without controls, intended solely for technical provenance, not a person's identity. The structural parser and SQL independently enforce the shape. SQL additionally validates real calendar dates, registered IANA timezone and exact civil/UTC round-trip, rejecting DST gaps and mismatches; either explicit UTC occurrence in an overlap is allowed. Unknown or approximate partner times are refused, never defaulted to noon.

Product consent is exactly `{storage:true,policyVersion:atv-input-consent/1,partner:true,continuity:false}`. A separate declaration is exactly `partnerConsent: {storage:true,policyVersion:atv-partner-storage/1,permissionDeclared:true,sharing:false}`. It records the authenticated submitter's declaration of permission for storage and processing of the other person's birth data, not verification that the other person consented. It must be explicit, initially unchecked in any eventual UI and renewed when partner data changes. It neither enrolls anyone in ATV+ nor permits contacting the partner, sending email, publishing or sharing results. Legal/retention review remains required before production activation.

The server copies the current COMPLETE, consented, EXACT owner profile at the expected onboarding revision. The partner's seven fields come only from this request; neither profile nor third-party identity is created. The immutable workflow input contains only the six fields for each birth plus product consent. Precision and the separate declaration remain bound to the original command in the private receipt `pair_product_requests`, together with the owner's natal version. Receipt data is private account-associated data, never telemetry. Authenticated callers cannot select/write receipts directly; only the narrow request RPC is executable. No service-role or anonymous execution is granted.

`request_pair_product_run` takes the existing owner advisory lock then the active profile row lock, uses the existing release/entitlement/quota checks and saves run, event, Library item and receipt atomically. Identical owner/key/command retries return the original run after profile edits, forgetting or release revocation. Any changed command or key from another bridge/generic request conflicts. Inactive owners cannot retry. Browser recovery must retain only a UUID, query read-only after an uncertain acknowledgement and never replay partner data automatically. Forgetting onboarding does not erase prior run copies; deleting a run cascades its receipt. Both copies have to be considered in retention/deletion review.

HTTP requires authenticated claims, same origin, a JSON body ≤4096 bytes, UUID-only 202 acknowledgements and private/no-store/no-referrer/noindex headers. A 202 is persistence, not completion. Unknown failures are redacted. No raw input is logged.

Calculation remains `atv-context-product-calculation/1.0.0`: separate deterministic Moon/Venus/Mars positions, partial and experimental, with no projected houses/angles, inter-chart aspects, compatibility scoring, claims about feelings, gender or destiny, or interpretation. Neither bilateral verification nor sharing is authorized by the calculation. Editorial/artifact publication remains independently gated.

Any partner edit or profile reconsultation clears both declarations. Every submission attempt clears the in-memory profile, partner draft and declarations.
